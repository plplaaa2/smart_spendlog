# Add-on 프론트엔드 아키텍처

## 1. 역할

프론트엔드는 `account_book/public/` 아래의 정적 웹 애플리케이션이다. 사용자는 이를 통해 거래, 알림, 규칙, 분석, 설정과 인증 기능을 사용한다.

## 2. 구성

| 영역 | 주요 파일 | 책임 |
|---|---|---|
| 애플리케이션 진입 | `app.js` | 화면 초기화와 공통 상태 연결 |
| 인증 | `auth.js` | 로그인 상태와 인증 요청 처리 |
| 대시보드 | `dashboard.js` | 요약 정보와 주요 지표 표시 |
| 거래 | `transactions.js` | 거래 목록·상세·입력 UI |
| 알림 | `notifications.js` | 수신 알림과 파싱 결과 표시 |
| 규칙 | `rules.js` | 자동 분류 규칙 관리 |
| 분석 | `analytics.js`, `analytics_*.js` | 기간별·유형별 분석 |
| 설정 | `settings.js` | 애플리케이션 설정과 백업 관련 UI |
| 공통 스타일 | `*.css` | 반응형 레이아웃과 컴포넌트 스타일 |

## 3. 화면 흐름

```text
로그인
  -> 인증 상태 확인
  -> 대시보드
       -> 거래 / 알림 / 규칙 / 분석 / 설정
       -> 각 화면에서 백엔드 API 호출
```

## 4. 프론트엔드 규칙

- API 호출은 인증 상태와 오류 응답을 일관되게 처리한다.
- 금액·날짜·거래 유형 표시는 공통 포맷을 사용한다.
- 서버 응답을 신뢰해 HTML을 직접 삽입하지 않고 사용자 입력을 이스케이프한다.
- 로딩·빈 상태·오류 상태를 화면별로 명시한다.
- 모바일과 데스크톱에서 핵심 거래 흐름이 모두 사용 가능해야 한다.

## 5. 확인이 필요한 항목

- 현재 사용 중인 API 응답 스키마를 라우트별로 정식 문서화해야 한다.
- 전역 상태 관리와 화면 간 캐시 정책을 코드 기준으로 확정해야 한다.
- 인증 토큰 저장 위치와 만료 처리 기준을 보안 검토 후 확정해야 한다.
